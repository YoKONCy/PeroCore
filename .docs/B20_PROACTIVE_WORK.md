# 主动建议与一次性跟进

## 运行归属

所有工作继续由 KernelScheduler 与 BackgroundTaskService 执行。计划、建议保存业务状态；ContextCompiler 只编译当前轮输入，不保存另一份工作正文。

- `set_reminder`：创建提醒、话题、预设反应，绑定调用角色和来源对话。
- `schedule_follow_up`：安排一次未来检查，须给出原因、具体检查内容和时间。
- `suggest_next_step`：保存待处理建议。用户查看依据和行动内容后，可以采纳或忽略。

## 生命周期

计划：`pending → dispatching → completed / dispatched`。派发失败退避重试，三次失败后进入 `failed`；用户可以重试或取消。领取带令牌和一分钟租约，过期领取者不能覆盖新的结算。所有角色的到期计划均被检查。

跟进和定时 Agent 任务在后台任务持久化后记为 `dispatched`；实际执行状态以关联后台任务为准。计划使用服务端生成的固定去重键，进程中断后再次派发会找到原任务。已入库但未提交 Scheduler 的排队任务在启动时补交；执行中断的任务保留检查点，供用户手动继续。

建议：`open → accepting → accepted`，或 `open → dismissed`。采纳意图先保存，后台任务使用固定去重键；扫描会恢复进程中断留下的 `accepting`。只有采纳接口会把建议变成用户发起的工作。

通知使用稳定通知 ID 与现有持久通知设施。外部副作用仍遵循工具自己的审批和幂等契约，不宣称跨进程恰好执行一次。

## 预算与权限

一次性跟进限一分钟至七天，单角色最多五个待跟进事项、每 UTC 日最多安排二十次，取消仍计入每日次数。执行预算为两分钟、八次模型调用、十二次工具调用。

`follow_up` 是请求级能力范围，只能与现有桌面 Channel 权限取交集。允许文件读取、查询、网页读取、截图和提出建议；禁止文件写入、命令执行、外部消息、MCP 和动态技能加载。跟进需要额外行动时提出建议，由用户采纳后进入普通后台执行。

陪伴模式仍使用 `ambient`，允许安静结束；一次判断未完成时不重复提交，失败和静默结束后同样冷却。陪伴开关不取消用户已经安排的跟进。

## 前端

`GET /api/scheduler/activity?agentId=...` 聚合已有后台任务、计划与建议。桌宠和任务中心共用活动数据，按场景分别呈现。

- 桌宠浮窗只在等待用户确认、存在待采纳建议、计划派发失败或有未读失败结果时出现；空闲、普通执行中和未来计划不显示常驻浮窗。提示使用小幅深色半透明面板，默认收起详情，可手动关闭；同一批事项不会因轮询再次弹出，新事项到来后恢复提示。
- 任务中心的活动区聚焦需要处理的事项，完整任务与历史保留在原有列表；建议、确认和失败重试使用统一的细边线、状态图标与操作层级。定时任务创建表单默认折叠，创建后收起。
- 近期工具结果由统一上下文窗口和预算管理，移除独立会话材料入口；输入台仅展示本轮显式附带的文件、选区和终端。工具来源与预算降级信息保留在诊断清单中。

Gateway 只通知投影失效，业务数据通过 REST 重读；角色切换丢弃旧响应，KeepAlive 隐藏停止刷新，权限或角色不存在时停止自动重试。等待审批的任务可以查看请求、填写附言并同意或拒绝本次操作。

## 提问未回答兜底

`ask_user` 固定等待十分钟，不新增工具参数或数据库字段。超时依据已有 `createdAt` 计算，说明复用 `responseMessage`：已经过去10分钟未响应，用户可能正在忙，暂时无法回应。

- 非必答问题以已有 `skipped` 状态结束等待，明确这是未回答，并非用户作出决定；Agent 可继续原授权范围内的工作或跳过相关部分。
- 必答问题保持 `pending`，释放当前执行等待，原有求助卡片继续接受回答。后台任务保持条件等待；普通对话稍后回答时沿原 Thread、当前模式和权限继续。
- 普通对话的五分钟执行超时在等待用户期间暂停，结束等待后恢复剩余预算。工具审批保持独立。
- 后台扫描依据原创建时间处理超时；重启后保留必答问题，不重置期限。必答超时说明只写入一次，避免持续提醒。

## 数据库

标准迁移 `0002_proactive_work.sql` 扩展 `scheduled_tasks` 并创建 `proactive_suggestions`。旧的 `is_triggered = 1` 记录迁移为完成态，避免升级后重放。Schema snapshot 与 journal 由 Drizzle Kit 生成；不增加启动时的临时建表逻辑。
