## 1. 已确认的产品方向与施工顺序

Arca 定位为 AI 原生办公套件。首批作品类型为文稿与演示，先把文稿创作做到足够完整。典型场景包括工作报告、项目方案、产品说明、会议纪要、研究材料与演示汇报。

本轮建设遵循以下顺序：

1. 明确文稿与演示的领域边界、工程格式和共享服务。
2. 补齐文稿的后端能力、持久化、前端编辑与操作逻辑。
3. 打通独立模式、挂载 infOS、AI 协作、版本审阅和成果交付。
4. 根据实际功能、异常恢复与兼容性证据验收文稿闭环，再补齐演示的后端与前端逻辑。
5. 文稿与演示的功能闭环均通过准入验收后，统一重写 UI。

功能阶段可以调整编辑 DOM、增加必要操作入口、修复布局或提供状态反馈，以便真实使用和验收。品牌视觉、配色材质、导航外观、装饰动效和整套组件视觉重写放在后续阶段，不能占用功能闭环的施工主线。

电子表格、邮件、日历与多人实时协同不进入本轮承诺范围。它们属于办公套件后续扩展，不阻塞本轮文稿与演示建设。

- `insertNodeAfter` 当前根据末尾排序键生成新键，需要确认“在后方插入”是否真的插在目标相邻位置。
- 文本提交后重新打开文档的流程，需要核验连续输入时光标、选区和其他未提交草稿能否保留。
- 独立模型分支当前将结果保存为建议文字，尚未形成与 infOS 协作一致的提案应用流程。

- 本地协作任务当前主要在客户端状态中维护，需要持久化到 Arca Host。
- 已有 `restoreCheckpoint` 是引擎级能力；单文档历史恢复不能直接覆盖整个引擎的其他文档。

## 3. 架构约束与需要先确定的契约

### 3.1 保留已有自治边界

- Document Engine 维护领域模型、事务、版本、提案与投影，不依赖 Vue 或 infOS 私有服务。
- Arca Host 管理文稿、资源、任务、模型与凭据，持有自己的数据权威。
- 客户端负责输入、选区、交互状态和投影；DOM 与浏览器缓存不能成为服务端之外的第二套正式文档。
- infOS 通过公开的 Application 协议提供可选角色协作、上下文与成果交付；主会话断线或失败不能级联终止 Arca 任务。
- 独立模式与挂载模式共用文档事务、提案、导入导出和任务实现，不维护两套业务逻辑。
- 本地模型配置与凭据由 Arca 管理；挂载模式新增宿主模型能力时使用明确绑定，不能悄悄覆盖本地选择。

### 3.2 文稿的权威模型

以现有结构化 Document Graph 为起点，在阶段 P0 确定富文本、段落样式、表格、资源、页设置与注释锚点的版本化 schema。

HTML、Markdown、分页结果和阅读视图均须声明自身的投影／交换属性。若提供可编辑源码面，必须明确其支持范围、解析与诊断、事务映射和无法表达的内容如何处理；不能把任意 HTML、DOM 与节点树同时当成权威正文。

编辑器框架的选择须先证明能表达既定 schema、中文输入、稳定选区和事务映射。不得仅为了工具栏外观选库，也不得绕开已有修订系统另存一份正文。

### 3.3 为演示保留独立作品模型

演示拥有独立的作品类型、稳定页面 ID、页面顺序、尺寸比例、元素、图层、备注与主题，不把文章按标题拆分的投影当成正式演示工程。

文稿和演示共享项目、资源、模型、任务、版本、审阅与导出基础设施。文稿转演示生成一份独立演示草案，记录来源修订；原文修改不会静默覆盖已编辑的演示。

### 3.4 共笔文坊参考的采用边界

参考本机 `VCP/VCPChat/ScriptoriumModules` 的以下设计：连续编辑与阅读预览、正文／源码／视觉定位、修改前后双重差异、署名提案、版本恢复与可携带成品。

采用这些产品能力时，先适配 Arca 的权威模型与 Application 协议。可编程岛、任意脚本执行、高级动画和完整 CSS 创作面不列为文稿首轮必达项；已有相关声明不得作为可运行功能对外展示。

## 5. 分阶段施工与依赖

各任务初始状态均为未开始。任务必须同时说明领域行为、客户端入口、持久化与恢复行为、验证证据，不能只以新增接口结项。

### P0：基线、schema 与施工契约

- [ ] P0-01 建立能力台账，逐项标注当前实现层、客户端入口、已知问题与验证状态。
- [ ] P0-02 固定文稿 schema、Inline 内容、段落样式、表格／资源、页设置及选区锚点契约。
- [ ] P0-03 明确 Project／Document／Presentation 关系及演示扩展点，解决当前固定 `article` 类型的后续迁移问题。
- [ ] P0-04 完成编辑器技术选型记录，比较结构化编辑、输入法、事务映射和可维护性；记录需要替换的局部实现。
- [ ] P0-05 定义领域操作、查询、任务、事件、错误与回执；Provider、Manifest、客户端类型同步纳入修改清单。
- [ ] P0-06 制定数据库与 `.arca` 格式升级方案，包含备份、旧数据迁移、失败恢复及导入兼容策略。
- [ ] P0-07 建立第 7 节验收样例与兼容性支持表，记录现状，不伪造通过结果。

出口：权威模型、兼容边界、编辑框架选择与迁移方式已有书面结论；后续阶段可以按稳定契约施工。

### P1：事务、保存与编辑恢复基础

依赖 P0。

- [ ] P1-01 扩展原子事务与前置条件，支持文字范围、格式与结构变更；同一批操作整体成功或整体失败。
- [ ] P1-02 修复相邻插入与排序策略，支持稳定的插入、拆分、合并和移动，避免时间戳排序键无限增长。
- [ ] P1-03 实现客户端编辑事务队列、输入合并与持久草稿；IME 组合期间不重建活动编辑 DOM。
- [ ] P1-04 已提交、排队和在途事务使用稳定标识；超时重试先核对回执，避免一次编辑重复应用。
- [ ] P1-05 区分“本地已保护”和“Host 已确认保存”；刷新、关闭和切文稿时保护未确认修改。
- [ ] P1-06 实现按逻辑操作分组的撤销重做；不能撤销其他作者的后续修改，冲突时保留用户操作意图。
- [ ] P1-07 完成单文档版本恢复：产生新修订、保留原历史，并保护当前草稿和其他文档。

出口：连续编辑、失败重试、关闭恢复与版本恢复不会丢失或重复覆盖正文；客户端状态与 Host 回执一致。

### P2：连续文稿与富文本编辑

依赖 P1。

- [ ] P2-01 完成光标、节点范围、文字偏移与版本的映射，明确 Unicode／UTF-16 偏移和换行规范。
- [ ] P2-02 支持中文输入、跨块选择、粘贴、拆段、合段、嵌套列表和常用快捷键。
- [ ] P2-03 接通 DOC-03 的行内与段落格式；批量格式操作与撤销形成同一事务。
- [ ] P2-04 接通段落样式、大纲、章节移动、目录、查找替换与统计。
- [ ] P2-05 编辑与阅读投影消费同一内容模型，保留未编辑内容、当前焦点和未提交草稿。
- [ ] P2-06 增加必要操作入口与错误反馈，禁用无能力支撑的操作，并说明原因。

出口：一份包含标题、列表、链接与多种格式的办公文稿能自然编辑，重开后内容和格式一致。

### P3：表格、图片、页设置与注释

依赖 P2；排版与导出接口在本阶段共同确定。

- [ ] P3-01 完成 DOC-05 的表格编辑、结构校验、选区、事务及撤销。
- [ ] P3-02 实现资源登记、内容寻址、引用查询和客户端预览，补齐 DOC-06；清理资源时保护历史与待审提案引用。
- [ ] P3-03 完成页设置、分页符、页眉页脚、页码和阅读分页；表格跨页、标题随段、超大图片溢出有明确处理。
- [ ] P3-04 完成评论与引用／脚注锚点随编辑迁移；内容删除后保留可辨认的失效状态。
- [ ] P3-05 提供公式、图表等扩展内容的明确支持与降级策略，避免空白占位冒充实际渲染。
- [ ] P3-06 共享编辑、预览与导出的字体、资源解析及排版规则，避免三套结果互相漂移。

出口：带表格、图片、注释和页设置的报告可以编辑、保存、预览并进入导出流程。

### P4：独立 AI 协作与统一提案闭环

依赖 P1 的事务与恢复、P2 的选区；结构／资源操作依赖 P3。

- [ ] P4-01 将协作任务持久化到 Arca Host，记录文稿、作者、模型、基础修订、范围、输入快照、进度、结果与错误。
- [ ] P4-02 定义任务状态与重试／恢复规则，客户端关闭后任务继续；Host 重启后明确恢复、待重试或失败状态。
- [ ] P4-03 本地模型与 infOS 协作者产出统一 ChangeSet；自然语言建议须经过显式转换与校验才能应用。
- [ ] P4-04 真实选区和章节范围约束上下文与修改目标；长文通过大纲、局部读取与检索构建上下文。
- [ ] P4-05 校验模型输出、目标存在性、格式与资源操作；生成成功、提案可审、提交成功采用不同状态。
- [ ] P4-06 审阅覆盖文字差异、格式／结构差异及必要的修改前后渲染效果；可接受、拒绝或请求调整。
- [ ] P4-07 审阅批准时重新校验基础版本；支持部分接受须先定义操作依赖，不能拆坏一个原子修改。
- [ ] P4-08 实现取消与提交的竞态规则：取消不回滚已确认提交，晚到结果不产生新提交，重试不重复应用。
- [ ] P4-09 模型失败、无模型、宿主离线均不影响手工创作；原文、草稿与已有提案可继续使用。
- [ ] P4-10 挂载模式接通明确的角色身份、上下文授权与成果返回原会话；投递状态与文稿保存状态分别记录。

出口：在独立模式完成“选区润色 → 审阅 → 接受 → 重开核验”；在挂载模式完成相同流程并将成果交回正确会话。

### P5：办公格式交换与成果交付
