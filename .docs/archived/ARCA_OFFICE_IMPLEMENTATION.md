## 2. 权威模型与编辑契约

- Document Engine 的结构化节点树仍是正式正文。客户端 DOM、HTML 和 Markdown 均为投影。
- 根属性 `officeSchemaVersion: 1` 标识本轮办公内容契约；第一次通过办公事务保存时写入。未知版本拒绝编辑，避免旧客户端覆盖新内容。
- 文字节点以 `text` 保存完整文字，以 `attributes.runs` 保存连续文字片段及标记。标记包括粗体、斜体、下划线、删除线、代码、字体、字号、颜色、高亮、链接与引用 ID。
- `inlineAst` 从当前片段派生；旧 AST 可以转换为片段，旧列表的 `attributes.text` 继续可读。历史 `text.replace` 默认保留旧操作语义，新编辑显式声明格式重建，防止旧修订回放失真。
- 段落属性包括标题层级、对齐、缩进、行距及分页标记；图片保存 Blob 地址、MIME、宽度、图注与替代文本；表格保存行、单元格及跨度，列宽按比例适配可用页面宽度。
- 选区由基础修订与两个 `{ nodeId, offset }` 端点组成。偏移按 JavaScript UTF-16 代码单元计算，换行统一为 `\n`。
- 本轮保留 `SemanticDocument.kind = article` 的存储兼容性；它表示既有文稿类型，并不将 Arca 定位为小说工具。Presentation 必须在 E1 引入独立作品模型，不能以标题拆分投影代替。
- Project 目前沿用文稿集合及 `.arca` 包清单；新项目领域实体、演示页与共享主题的完整迁移尚未完成。

编辑实现选择：本轮采用独立的 `OfficeSession` 和结构化 `contenteditable` 适配层，不新增编辑器依赖。输入、选区、事务、持久化与 DOM 渲染分别维护。中文组合输入期间暂停格式工具及活动 DOM 同步，组合结束后形成编辑事务。此实现尚需真实输入法和长文压力验收，不能仅凭工具栏齐备认定最终编辑器选型通过。

## 3. 保存与历史的一致性

1. 每次本地逻辑操作先更新内存文稿并写入本机草稿；连续输入合并为撤销分组。
2. 发出请求前持久化完整请求，包括基础修订、事务 ID、时间、意图与内容快照。
3. Host 从基础快照编译领域操作，核对代次与文稿修订，原子提交并返回回执。
4. 未知回执重试沿用原事务。服务端已经写入时返回原回执；请求内容不同则拒绝复用同一个标识。
5. 保存期间的新输入继续留在当前草稿，旧回执不能把它覆盖回去。
6. 新修订冲突时保留草稿，可下载备份或另存副本。另存期间继续输入时不丢弃新增内容。
7. 历史恢复读取指定文稿的旧快照，再提交一笔新事务；不恢复整个引擎，不影响其他文稿。

历史回放校验目标修订的 Root Hash。只含快照的工程记录 `historyBase`，导入后的操作从该基础回放；旧工程没有保留的来源历史不伪造为空文稿。修订序号继续递增。

## 4. 协作任务与审阅

独立模型任务保存在 Arca 数据目录的 `office-tasks.json`。任务保存作者、文稿、基础修订、真实范围、指令、模型配置快照、进度与结果；模型凭据仅通过已有凭据引用读取，不把密钥放进客户端任务结果。

模型输出须通过 JSON 结构、节点范围、原文匹配与长度校验，随后编译为 ChangeSet 并经引擎校验。客户端看见“等待审阅”后，可查看原始差异与修改前后预览；批准提交仍重新检查基础修订。

取消后晚到的模型响应不创建新提案、不提交文稿；已经确认提交的提案不因取消而回滚。Host 退出时工作中任务转为可说明的失败；重启可识别已生成提案。任务文件损坏会关闭协作队列并保留原文件，手工文稿继续可用。

主要新增操作：

- `document.apply_edit`、`document.snapshot_at`、`document.restore_revision`。
- `document.duplicate`、`document.set_status`、`document.preview`、`document.changeset.preview`。
- `office.task.submit`、`office.task.list`、`office.task.cancel`、`office.task.retry`。

Provider、应用 Manifest 与客户端调用已同步；写入操作继续要求 Surface Session 与幂等标识。

## 5. 兼容与数据保护

- SQLite 存储 schema 升至 2；版本升级前写入带随机名称的旧 checkpoint 备份。失败时不继续标记升级完成；本轮没有实际打开或迁移用户运行数据。
- `.arca` 新导出标记格式 2，继续接受格式 1／2。旧客户端不应读取含新操作的格式 2 包。
- 完整工程资源扫描覆盖当前节点、历史基础、操作日志与待审提案，避免替换图片后丢掉历史资源。没有新增自动物理清理。
- HTML 投影转义正文与属性，限制链接及图片类型；预览 iframe 不启用文稿脚本。导出预览固定到已确认修订，先处理草稿保存问题。
- 正文事务上限约 15 MB、最多 20000 节点、嵌套不超过 64 层；超出范围返回明确错误，保留当前草稿。
- 单份 HTML 预览／导出最多内嵌 20 MB 图片；超过限额时拒绝生成，原工程及资源不变。
- 旧版文本草稿仅在基础修订与节点代次匹配时迁入新缓存；冲突旧缓存保留并可纳入备份。损坏的新缓存原文也随备份保留。

## 7. 首轮界面调整（已由第 8 节的确认设计替换）

本次施工依据用户对整体布局、精简文案和右上角停止应用的后续确认，优先重写文稿界面。

- 全局顶栏统一提供文稿标题、保存状态、设置与右上角“停止应用”。首页、工作区与设置保持同一应用结构，窄窗口继续显示停止按钮。
- 首页改为文稿库，支持最近修改、全部、收藏、归档、回收站，提供搜索、排序、列表／网格视图，以及重命名、创建副本、归档与恢复。收藏与视图偏好保存到本机。
- 工作区以正文为中心，大纲／文稿导航可收起；属性、协作、审阅、评论与历史共用一个按需右侧面板。正文编辑会话在切换阅读／审阅模式时保持挂载。
- 编辑工具按“开始、插入、布局、审阅”分组；表格工具按选中状态出现，图片与段落属性放入右侧面板。查找替换按需展开，文字选区提供浮动工具条。
- 提供页面／连续视图及缩放。页面视图用于纸张宽度与边距编辑，不代表精确分页；打印仍使用已保存版本的 HTML 投影。保留 HTML 导出、预览打印、草稿备份与 `.arca` 工程交换。
- 审阅提供文字差异与修改前后排版对照；接受、拒绝、请求调整与历史版本恢复继续调用真实领域操作。
- 设置改为模型、编辑、协作、外观与连接；技术信息收进诊断折叠区。移除常驻的技术编号、术语说明、材质装饰和像素标签，改为中性明暗表面与紫色强调。
- 应用内对话框统一处理初始焦点、Tab 循环、Escape 和背景交互隔离。原生链接输入与丢弃草稿确认改为应用内对话框。

### 停止与草稿保护

托管实例调用 infOS 应用控制面的停止操作；独立实例使用新增 `application.stop` 能力。该操作要求与来源节点绑定的编辑 Surface Session 和幂等标识，回执发出后停止本地任务与 Host，独立入口再退出进程。客户端等待停止结果或连接关闭后展示停止状态，并尝试关闭桌面标签／窗口；浏览器不能自动关闭时保留停止页面。

未保存内容提供“保存并停止”或“保留草稿并停止”；草稿缓存不可恢复、输入法组合未完成、图片上传未完成或前台事务进行中时阻止停止。停止失败恢复编辑与保存调度；成功停止后关闭自动重连。暂停会话后卸载编辑器不会重新补发保存。

托管停止会先阻止对应实例的新协作并取消宿主角色任务，再请求 Arca 自身收口本地任务与资源；异常断联由宿主实例监视器回收失去归属的角色任务。已完成、待人工审阅的提案保留。独立实例仍由自身生命周期负责，宿主退出不强制停止外部实例。

### 本轮验证边界

## 8. 「文稿编辑室」确认设计实装（2026-10-17）

用户确认独立设计预览后，本轮以文稿库、正文编辑和协作审阅三个画面为实施基准，未引入新的编辑器或 UI 依赖。

- **视觉与框架**：采用确认稿中的纸页、墨色、暖棕强调与衬线 Arca 字标。全局顶栏显示文稿标题、保存状态、设置与右上角「停止应用」；设置、弹窗与菜单同步使用这套色板和控件规范。
- **文稿库**：移除常驻分类侧栏，改为横向最近／全部／收藏与底部归档／回收站。默认纸页预览；单份文稿显示较大的正文摘览和继续编辑、真实字数、修改时间、语言与大纲，多份文稿使用纸页网格。保留列表、排序、收藏、重命名、副本、归档和恢复。
- **真实预览**：DocumentCover 读取文稿快照，按正文树顺序生成摘览，不填入设计稿示例文字。图片通过 Blob 服务读取；未连接或读取失败保留明确状态。列表分批显示，避免一次挂载整个库的预览；预览为正文摘览，不宣称完整分页或忠实打印缩略图。
- **编辑布局**：文件／开始／插入／页面／审阅作为统一菜单层。编辑器分组工具移到大纲与正文上方，减少重复操作栏。主区以纸页为中心；右侧属性、协作、评论、历史或审阅打开时收起大纲，关闭后恢复原导航状态。文稿编辑会话在阅读与审阅间保持挂载。
- **纸页与标尺**：字体层级、纸页边缘和间距按确认稿调整。页面标尺按实际正文宽度与页边距计算刻度，缩放与纸页共用同一容器；窄窗口关闭标尺。文稿名称作为阅读用标题展示，正文首个标题已经同名时避免重复；该名称仍为文稿元数据，不会额外写成正文节点。打印／HTML 投影继续以正式正文为准。
- **协作**：真实协作者选择、选区／章节／全文切换、修改要求、润色／精简／整理结构快捷填写、选中文字引用、附加要求与任务活动均接入现有任务流程。快捷填写只填入指令，提交后仍生成待审提案。
- **审阅**：从提案的基础修订读取原文，将文本修改放回正文中显示删除与新增，支持「显示改动／修改后」。共同前后缀的差异边界避免拆开代理字符；同一段落多次替换合并展示最终结果。新增／删除／移动节点及图片等复杂变化默认进入真实的前后排版投影，文字与排版视图都保留入口。接受、要求调整、拒绝继续走现有领域操作与修订校验。
- **交互保护**：保留保存、恢复、输入法、图片上传与停止保护；补齐菜单外部点击／Escape 收起、大纲定位与活动状态、只读工具提示、预览图片生命周期和旧审阅状态重新进入时的原文加载。历史恢复按文稿可写状态判断，阅读或审阅模式下仍可进入恢复确认；格式菜单定位在触发按钮下方。

本轮仅阅读源码、编辑文件并目测 review，未运行 TypeScript／Vue 类型或模板检查、lint、格式化、构建、测试、应用或截图验收。第 6 节的历史检查不覆盖这次变更。实际窗口观感、中文输入法、打印和长文性能仍需后续运行验收；Office 文件导入继续排除在本轮之外。

## 9. 材质、层次与交互精修

依据用户后续确认，本轮在「文稿编辑室」布局上继续细化，未引入第三方动效库或新增字体资源。

- **视觉层次**：工作台使用柔和的明暗变化，工具与面板带固定方向的边缘高光；纸页、菜单和弹窗分别使用接触阴影与环境阴影。浅色与深色主题分别定义光照、阴影和纸面参数。标题、元信息与表单字号重新拉开层级；单文稿首页移除纸页下方的重复标题，保留原有收藏与更多操作。
- **操作反馈**：文稿悬停轻抬、按下回落；按钮按压、输入聚焦、工具切换、菜单与弹窗进入均采用短促过渡。首页分类与工具分类的指示线独立移动，按钮和焦点保持稳定；次要文稿操作预留空间，在鼠标悬停或键盘焦点进入时显示，触摸设备保持可见。
- **侧栏与阅读位置**：侧栏退出时立即停止交互并脱离布局，纸页在最终布局上仅做平移；位移按当前缩放比例换算，不在过渡中连续改变正文宽度。切换前记录可见段落的位置，切换后校正阅读滚动位置。快速连续切换会取消旧位移动效并丢弃过期异步结果。
- **键盘与焦点**：菜单支持方向键、Home／End、Escape 与焦点离开后收起，输入控件继续使用自身的方向键行为。关闭菜单或侧栏时恢复适当焦点；协作与评论输入出现时聚焦输入框。退出中的侧栏和弹窗设置为不可交互，防止动画期间误触。
- **真实状态反馈**：协作进度提示依据真实任务状态显示；保存完成后提供短暂收束反馈。审阅提交成功后显示结果、恢复阅读位置，并短暂标记当前可见的已接受文本段落；连接缺失或提交失败不显示成功反馈。
- **动效偏好**：CSS 动效与纸页位移、审阅反馈共同遵循应用的完整／减少／系统偏好；减少动态效果时取消纸页抬升、按钮位移、过渡与循环动效，保留状态文字和焦点提示。

本轮仅进行源码阅读、修改与目测 review。依用户持续要求，未运行静态类型／模板检查、lint、格式化、构建、测试、应用或视觉截图验收。实际光影、动效节奏、缩放与侧栏连续切换效果仍需运行验收；既有保存、停止与领域事务继续沿用原流程。

## 10. 静态头像、选择组件、设置与书本交互

依据用户提供的三张截图，本轮继续实装以下改动：

- **角色静态头像**：协作状态接口新增可选头像地址，从角色档案读取是否存在头像资源。客户端统一相对于 Kernel 解析静态角色资源接口；同时兼容旧接口未返回头像字段的情况。协作者选择、审阅与设置复用 ArcaAvatar，读取失败或本地模型使用图标回退，移除角色首字母占位。
- **统一选择组件**：工具栏、协作、段落属性、文稿排序与设置改用 ArcaSelect。浮层挂载到页面根部，使用不透明的明暗主题表面；支持选中标记、角色头像、字体预览、键盘移动、首尾定位、输入定位、Escape／Tab、失焦关闭与屏幕边缘翻转。数值标题级别与空值思考配置保持原值类型，原有编辑选区仍由编辑会话保留。
- **设置重写**：移除原先纵向分类和宽行表单，改为顶部分类、模型配置列表与紧凑编辑区。保留真实模型选择、保存并使用、连接测试、密钥保留和高级参数。编辑宽度和主题采用可选预览卡片，协作显示静态头像；外观即时应用并保存偏好。新增配置聚焦名称输入，分类切换与高级区域使用短促反馈。
- **书本与文稿进入**：封面、内衬、纸芯、内页与封底分别绘制，以书脊为轴悬停微开、点击完整展开。加载成功后，支持原生视图过渡的环境共享内页与编辑纸面的过渡；其他环境使用不可交互的内页浮层衔接。限制过渡纸面高度，避免长文按全文高度展开；失败还原、临时样式与图片地址的生命周期保持清理。选择大纲条目直接定位，减少动效时直接打开。

本轮仅进行源码目测 review 与修复，未运行程序性静态检查、构建、测试、应用或截图验证。图片地址可达性、下拉交互、原生／备用书本过渡、长文及不同窗口的实际观感仍需运行验收；上述实现不代表已经通过视觉或运行验收。Office 格式导入继续排除在范围外。

后续根据用户对翻书过快的反馈，将悬停微开调整为 620ms、点击展开调整为 820ms、纸面进入调整为 650ms，并采用起步缓慢、末段收稳的缓动。原生与备用过渡共用同一套样式时长参数，失败收回调整为 320ms；加载与展开继续并行，不增加人为等待。此次仅做源码目测修改，未运行检查或应用。

## 11. 浅色编辑室

依据用户要求实装浅色模式的完整界面，以米灰工作台、暖白纸面、浅布面封皮与铜棕操作为同一套视觉基础。

- 新增独立浅色样式，覆盖文稿库、应用顶栏、编辑工具、左右面板、页面与连续视图、审阅标记、选择浮层、菜单、设置、弹窗及滚动条。输入区域与卡片分别处理明暗、边界与焦点，浮层保持不透明；主按钮使用深铜棕底与浅色文字。
- 书本采用浅布面、象牙色纸芯与暖色接触阴影，内页保持暖白；书本阴影改为明暗主题分别提供参数。沿用上轮放慢后的翻书时长与减少动效规则。
- 主题选择解除宿主锁定：明确选择浅色或深色时采用本地选择，跟随模式优先使用主窗口主题，无宿主时跟随系统。设置卡片显示当前选择并持久化，宿主后续更新不会覆盖明确选择。
- 挂载界面前先解析已保存的主题偏好；编辑器的默认文字颜色控件同步主题，保留正文中已明确设置的颜色，不因主题切换修改文稿内容。
