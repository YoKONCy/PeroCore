# 桌宠与 Bot 的持久任务闭环

## 本轮实现

- 保留 `background_tasks` 作为唯一任务事实，新增修订号和生命周期数据；执行仍走 `KernelScheduler`，没有增加管理 Agent。
- 生命周期保存目标、完成条件、简短计划、交接摘要、时间或任务等待条件、来源、恢复策略、截止时间与累计预算。
- `finish_task.task_result` 提交 `continue / wait / deliver / blocked / failed`。未明确交接不自动算作完成；证据引用必须对应本段实际成功的业务工具记录。
- 到期或关联任务完成后唤醒原任务。等待用户、时间或其他任务时释放执行槽位。任务依赖的循环检查在数据库事务内再次执行。
- `ask_user` 和工具审批在后台任务中持久等待；重启后仍可回答。普通即时聊天继续使用原来的等待方式。
- 用户修改要求时增加修订号；迟到工具结果、检查点和执行交接不能覆盖新要求。
- 只读任务可自动恢复；写入前保存未确认动作，结果及检查点保存后才清除。不明动作需要用户明确核验后继续。
- 分段等待保留受管终端。暂停、阻塞、取消和结束时回收；重启后发现受管终端丢失则阻塞，防止盲目重建进程。
- 累计预算覆盖深层 LLM 调用及工具调用，每段继续使用既有调度预算。达到累计预算、截止时间或段数上限需要用户处理。

## 桌面与远程操作

- 单个 `manage_task` 工具提供创建、查询、调整、暂停、恢复、取消、回答、审批和投递核验。
- 主应用和社交通道共用 `TaskControlService`。当前远程入口只开放给已绑定主人的 QQ 私聊，模型不能传入操作者身份。
- 来源包含平台、Bot 账号、会话、发送者和消息 ID。创建按来源消息去重；后续变更要求任务 ID 和当前修订号。
- 每条来源消息最多创建一个持久任务；多步骤目标保存在该任务的计划中。
- 社交侧先列出或读取任务再操作；歧义需要澄清。审批仅允许逐次决定，不将远程回复转换为通用权限。
- 任务详情支持查看计划、交接和预算，调整要求、完成条件、截止时间与预算，以及核验不明动作。

## 完成与投递

- `completed` 表示执行器明确交付。`verification` 分别表示未核验、执行器已报告、有实际工具证据；不把模型自述标记为自动验收通过。
- 任务完成、失败、阻塞或需要用户决定时，同事务写入现有 Kernel Outbox。
- Outbox 消费者只创建按渠道投递记录，实际发送独立处理，社交离线不阻塞内核事件流。
- 重要应用通知入库，客户端重连后补送未读记录；原聊天结果回填与投递结算同事务，避免重复追加。
- 社交结果使用保存的 Bot 账号和来源私聊。绑定变化时停止向旧来源投递。
- 离线在发送前重试；发送过程中超时或崩溃标记 `uncertain`，不自动重复。用户可在任务详情或远程明确确认已发送、未发送后重发。
- 普通进度变化不产生重要通知。桌宠仅在需要处理时提示，完整内容保留主应用。

## 数据库与接口

- 标准迁移：`0005_task_lifecycle.sql`、对应 schema snapshot 与 journal。
- 新增任务字段：`revision`、`lifecycle_json`；新增 `task_deliveries` 表。
- 历史完成记录保留原语义，生命周期读取为 `unverified`，不补造证据。
- `POST /api/background-tasks/control`：角色 ID 加任务操作参数。
- `GET /api/background-tasks/:id/deliveries`：投递状态。
- `POST /api/background-tasks/:id/deliveries/:deliveryId`：用户核验后标记或重发。
- 原审批提交接口增加 `expectedRevision` 与 `approvalId`，阻止旧页面批准新的审批。

## 边界

- 当前不开放群聊控制；没有账号绑定时不降级授权。
- 不承诺外部消息恰好发送一次；适配器缺少幂等能力时保留不确定状态。
- 没有为任意自然语言目标增加通用自动验收模型；完成条件、产出引用和工具证据可供核验。
- 持久任务暂不使用 `run_script` 聚合调用，避免绕过逐工具检查点和恢复边界。
- 本轮只执行不产出构建文件的静态类型与模板语法检查；没有执行迁移、测试、构建或打包，也没有完成实际 QQ 联调。
