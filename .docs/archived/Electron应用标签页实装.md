# Electron 应用标签页实装

## 本轮范围

代码已接入，尚未进行构建或运行验收。

- 固定 PeroperoChat 首页保留现有综合面板及聊天状态。
- 顶部 `＋` 创建新标签页，支持网址、搜索、Arca 和常用工作入口。
- 浏览器使用原生 `WebContentsView`，提供地址栏、后退、前进、刷新与停止加载。
- Arca 以单实例标签打开，复用原有 UI 和后台 Host。
- 深浅主题、应用更新中心和窗口控制统一放在标签栏右侧。
- 侧栏移除应用分组，社交配置归入设置；Arca 的 Host 启停、连接与诊断归入其自身“设置 → 连接与运行”。
- `Ctrl+T`、`Ctrl+W`、`Ctrl+Tab`、`Ctrl+Shift+Tab` 与 `Ctrl+L` 在主页面和子视图中使用同一处理逻辑。
- 视觉使用现有 UI 语义令牌、PixelIcon 和像素品牌字，沿用产品的粉蓝紫强调色与细边框。

## 所有权

`electron/main/windows/desktopTabs.ts` 是桌面标签的权威管理器。`useDesktopTabs` 订阅快照并忽略旧 Revision；前端不复制应用进程或任务状态。

| 对象 | 生命周期 |
| --- | --- |
| 首页 | 随综合面板创建，切换到子应用时保持挂载 |
| 浏览器标签 | 切换时隐藏，关闭时释放网页资源 |
| Agent 临时浏览页面 | 沿用空闲回收；用户主动查看后转为保留页面 |
| Arca 界面 | 单实例，关闭前检查未提交文稿 |
| Arca Host 与后台任务 | 由原有应用控制面管理，关闭标签不停止它们 |

主窗口关闭与应用退出会进入标签关闭流程；用户取消草稿确认时取消关闭。Renderer 重载期间先隐藏原生视图，再从主进程快照恢复标签与布局。窗口彻底关闭后释放子视图，本轮没有增加跨应用重启的标签恢复。

## 浏览器与 Agent

`ElectronBrowserRuntime` 中的页面目标改为 `view + tabId`，保留浏览器能力协议和持久会话分区。用户当前查看的标签与 Agent 的 `activeTargetId` 分开管理。操作队列使用独立异步上下文固定本次目标，取消后的回调不能自动落到其他网页。

操作遮罩是目标视图的子视图，仅锁定对应页面；顶栏仍可切换和新建标签。用户保留的页面不被 5 分钟 Agent 空闲回收销毁。浏览器下载仍沿用既有运行时的授权配置。

## Web 子应用接入

受信任的 Electron 主进程适配器调用 `desktopTabs.registerApplication()` 声明：

- `id/title/description/icon`：启动台信息。
- `url`：固定入口，或由前端适配器通过受信任控制面解析后提供入口。
- `acceptsUrl`：主进程验证入口及重定向的 URL 边界。
- `multiple`：可选多实例，默认单实例。
- `preload`：是否启用受限应用桥接，不提供完整系统 IPC。

当前内置接入 Arca；后续带 Web UI 的子程序可以沿用该合同。原生 EXE 窗口没有被通用嵌入。

Arca 开发入口使用配置的本机 UI Origin，发行包使用本机 Daemon 的 `/applications/arca/` 路径。嵌入页面隐藏自己的窗口标题栏、跟随宿主主题，并通过受限通道上报未提交文稿状态。本地文稿草稿保留原有持久化逻辑。

Arca 的自身控制面通过 `arca-host:control` 访问，限定为 status/start/stop/reconnect 四种操作，并校验调用方为当前 Arca 标签。Electron 主进程持有后台鉴权信息，页面不取得系统 Token。浏览器模式沿用 HTTP 控制面。离线或自动启动失败时打开应用内连接设置，提供启动与诊断入口。

拖动排序、拖出独立窗口、分屏及跨重启恢复不属于本轮范围。
