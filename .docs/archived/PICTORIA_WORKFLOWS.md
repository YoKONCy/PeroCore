## 页面与操作

画布顶栏进入“工作流”。工作流编辑页复用画布的颜色变量、自定义选择浮层、主题切换、平移缩放、多选、复制、撤销／重做、搜索跳转与整理过渡。空白处左拖平移；手形、空格与中键在捕获阶段接管视野拖动，避免同时移动节点。Shift＋左键拖动追加框选，可从空白处或节点上开始；Shift 单击切换选中状态。

- 左侧目录按步骤名称与模型搜索，支持加入已配置的 API、LLM、已发布工作流。
- 中央显示输入、处理节点、输出。处理节点提供左右字段端口及首字段的上下端口；连线方向与布局随草稿保存。
- 右侧配置固定值、引用、多项引用、字段路径、备注、对外输入输出及自然语言输入说明。
- 底部按需展开校验、试运行和发布历史。错误定位到节点／字段；运行详情显示实际可解析输入、输出、状态、耗时和异常。资源可预览、下载、加入当前创作画布。
- 新建步骤支持 LLM 配置与通用 JSON／multipart API 服务配置；API 高级字段映射、认证及异步查询由作者填写。
- 普通界面使用短文案；解释放入教程页。

## 草稿与发布

### 教学模板与备注

工作流选择器的“创建示例”和教程页的“创建示例工作流”会创建独立草稿，不覆盖当前工作流。示例演示创意输入 → LLM 润色 → 图像生成 → 多参考图编辑 → 图片输出，保留真实字段类型与数组引用连线。

示范节点的 `example` 只保存名称、用途及输入输出 Schema，不创建 API、凭据、模型或可执行步骤。客户端禁用未配置示例的运行／发布按钮；后台 `compileDraft` 同时拒绝缺少真实步骤版本的节点。选中节点可选择已有步骤或配置一个真实步骤，同名输入引用保留；其他字段和输出仍需校验。

通用 `NoteCard` 说明整体流程、输入输出及每个处理步骤。草稿 `notes` 保存标题、正文、位置及可选节点锚点，支持编辑、添加、删除、拖动、搜索、复制、撤销／重做、自动保存与导入导出。锚定卡片随节点移动与整理；节点删除后保留说明卡片的原位置。备注与示范 Schema 不进入发布的执行定义，也不会注入模型上下文。

`workflow-draft` 保存可未完成的文档：空节点列表、可未选步骤的节点、参数引用、坐标、备注、接口、端口方向与视野。空名称也能保存，发布时要求有效名称。

对外操作：

| 操作 | 用途 |
| --- | --- |
| `workflow.draft.list/get/save/delete` | 工作流草稿管理，写入使用 `expectedRevision` |
| `workflow.validate` | 校验当前未保存文档或已保存草稿，返回 `valid,issues,definition` |
| `workflow.draft.publish` | 校验并保存执行定义、发布快照和步骤版本；同事务更新草稿发布信息 |
| `workflow.history` | 当前角色的发布历史 |
| `workflow.draft.restore` | 将某个发布版本恢复为草稿，不改变当前发布步骤 |
| `step.version` | 读取固定版本的节点定义 |

旧 `workflow.save/get/list/publish` 执行定义接口继续兼容；旧定义可转换为编辑草稿。发布后步骤自动进入画布和 Agent 目录，作者的 `usageDescription` 继续进入工具说明，不做自然语言与 tags 的转换。

客户端自动保存并保留本地草稿；拖动时延迟本地落盘。并发版本冲突阻止覆盖，可以另存副本或导出。导入 JSON 总是使用新工作流 ID，已有草稿与发布版本不会被覆盖。

删除工作流移除草稿和当前可用步骤，保留素材、既有任务快照和发布历史记录。历史任务不重新生成，也不回滚文件。

## 输入引用

保留原有三种引用，并加入数组组装与字段路径：

```json
{
  "prompt": { "node": "polish", "output": "text" },
  "images": {
    "array": [
      { "node": "generate", "output": "images" },
      { "input": "reference" }
    ],
    "flatten": true
  },
  "image": { "node": "generate", "output": "images", "path": [0] }
}
```

- `{literal:值}`、`{input:字段}`、`{node:节点ID,output:字段}` 继续有效。
- 引用上的 `path` 使用字符串／非负整数数组，支持结构化字段与数组序号。
- `{array:[引用…],flatten:true}` 按顺序组装并展开一层数组；不会转换内容、去重或调整提示词。
- `{select:引用,path:[…]}` 支持对子工作流输出或组装结果再取字段。
- 每个数组最多 64 项，引用嵌套最多 16 层，总引用检查数量有限制；禁止原型相关路径，不执行脚本或表达式。

依赖分析、循环检查、子工作流展开、执行调度、失败分支跳过和结果解析均遍历复合引用。未传入的子工作流参数不借用外层同名输入。

校验提前检查已声明字段、必填输入、已知类型、固定值、循环、步骤版本和服务凭据。动态路径无法确定时返回警告，执行时仍按实际值及 JSON Schema 校验；不承诺静态预测模型输出。

## 试运行与恢复

试运行经过现有 infOS 调用关联和独立内部会话，再交给 Pictoria 后台执行。每个工作流使用独立测试画布 ID，不直接修改当前打开画布的数据版本；用户可将测试输出加入当前画布。

试运行会调用真实服务，可能产生费用；教程已说明。LLM 使用既有模型授权和凭据桥接，没有绕过授权。

提交前持久化稳定请求身份；收到接受结果后立即创建本地占位并保存任务 ID，再查询详情。详情断线不创建新生成任务，后台状态由后续查询补齐。提交结果未知时重复点击复用原请求键；明确完成后再次运行才创建新身份。

修改执行参数、步骤版本或接口后，已有运行标为旧结果，不将旧状态标记到未运行的新节点上；平移与布局调整不会改变执行归属。

试运行使用同一套远程任务续查、提交核验、下载检查点、退避与取消机制。恢复入口可绑定远程 ID；重新生成仍需明确勾选，可能再次计费。规则见 [请求与恢复](PICTORIA_RECOVERY.md)。
