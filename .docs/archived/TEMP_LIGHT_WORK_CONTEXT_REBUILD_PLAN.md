# 主 Agent 轻量工作上下文改造计划

> 状态：2026-10-09 已收敛为近期工具结果的标准上下文管理。下文旧 ToolObservation、材料视图和 WorkContinuation 方案保留为历史，当前决策以本节及 A09、B01、A03 为准。代码与迁移已修改，本轮未运行构建、测试或迁移。
>
> 范围：主 Agent 的 `desktop` 对话及工作区 Tab。保持主 Agent 负责日常轻量工作、自治 Application 负责重活任务的分工；不为主 Agent 引入完整 IDE、全项目语义索引或常驻压缩 Agent。

## 2026-10-09 收敛决策

- 删除“最近 32 条按提问召回最多 8 项”和开头 1400 字摘录；删除独立材料 API、前端入口、Repository 和旧观察服务。
- 近期文件、搜索、网页和终端读取结果只在进程内缓存原始返回文本，按 Thread、Agent、Pair 隔离。来源、版本、范围、读取参数随原有助手消息元数据保存。
- 当前消息窗口决定工具结果生命周期；统一 Region 预算按新近顺序选择，正文无法放入时退化为来源。文件版本变化、退出窗口、回滚和内存回收后释放正文；重启后来源仍可重读。全进程正文缓存上限为 32 MiB。
- 审计、原始转写和初始提示词持久化快照不写入缓存正文。诊断清单用 `fallback` 记录预算降级。
- ReAct 达到输入上限时将较早的可重读结果退化为来源，移除额外模型生成工作续接摘要的路径，保留最近一次读取原文。
- 本轮工作区文件、选区和终端入口保留；独立跨轮材料管理入口移除。后台任务和 Realm 使用各自执行上下文。
- 新增标准 `0003_remove_tool_observations` SQL、journal 条目与 schema 快照，删除旧摘录表；对话消息不修改。相关回归用例已更新及补充，未经用户允许不执行构建或测试。

## 1. 问题与目标

当前有四种容易混称的对象：Principal Workspace 是 Agent 的文件资源；ExecutionSession 决定工具执行根与权限；工作区 Tab 的当前文件/终端是本轮 UI 焦点；`FlowState.workContext` 是工具读取正文的跨轮临时副本。它们不应共享同一个生命周期。

现有跨轮链路为：工具结果在 ReAct 本轮使用，`ConversationTurnService.captureWorkContext()` 从 `contentBlocks` 提取文本，写入 `work_context_entries`，下一轮由 `ContextCompiler` 拼入 `250_draft_flow`，再按固定对话轮数过期或由 `manage_work_context` 手动整体压缩/清空。主要问题：

- `file:{path}` 作为去重键会让同一文件的不同读取区间互相覆盖；来源缺少版本、范围、截断与可回读状态。
- `toolBlock.result` 先截取 8000 字符，之后才解析 `read_file_range` 等 JSON，截断可能让自动采集失败。读取正文还可能随 `contentBlocks` 写入 Assistant 元数据，与“只在本轮内存中”的注释不一致。
- 工作正文被整体塞入 system 槽位，又在 Region 选择之后单独按字符串裁剪；Manifest 不能准确解释每份工作材料的去留。固定轮数不能判断材料是否仍适用。
- 工作区 Tab 只传当前文件路径与终端 ID，没有文件版本、选区、未保存状态；文件树/终端使用的 fallback Thread 可能与 Copilot 的真实 Thread 不同。非流式 `/api/chat` 尚未透传 `workspaceContext`。

**目标**：本轮工具结果足够完成当前判断；跨轮自动保留“读过什么、来自哪个版本、如何再取”的证据；仅在容量需要时压缩旧工作过程。Agent 不承担日常写工作日报或清理上下文的责任。所有进入模型的材料由 ContextCompiler 统一选择、计量和记录来源。

## 2. 概念与权威边界

| 对象 | 权威与生命周期 | 模型输入 |
| --- | --- | --- |
| Principal Workspace | Agent 长期文件资源，由文件系统和受控文件服务持有 | 按需读取，不因打开工作区自动注入整棵目录 |
| ExecutionSession / Task Workspace | Thread 或 Task 的执行资源与权限；任务结束回收 | 只投影必要的执行位置与状态 |
| WorkspaceFocus | 当前请求的 UI 焦点；切换 Agent/Thread 即失效 | 经后端校验的本轮临时 Region |
| ToolObservation | Thread × Agent × Pair 中一次工具观察的来源与版本记录 | 编译器按需选择的证据 Region；不等于长期记忆 |
| WorkContinuation | 容量压力下对旧工作过程生成的续接摘要 | 替代已覆盖的旧活跃输入；保留原始记录与近期原文 |
| FlowState | Agent 私有目标与私有事实 | 独立私有状态 Region；不再承载工作材料 |

**决策**：移除“工作心流”作为可持续编辑的正文状态，包括 `FlowState.workContext` 的自动追加职责、常规 `manage_work_context` 操作和“保留若干轮”的产品设置。保留 `currentGoal/privateFacts`，但工作进度由 Thread/Execution 表达，工具证据由 ToolObservation 表达。统一编译入口，不合并这些对象的持久化权威。

## 3. 后端最小方案

### 3.1 工具结果进入观察记录

在工具结果尚未转换为 UI/审计预览之前，从结构化结果建立 `ToolObservation`。首期覆盖 `read_file`、`read_file_range`、`code_search`、`web_fetch` 和浏览器正文读取；终端只记录执行身份、状态与输出游标，不自动复制整段终端日志。

每项至少包含 `threadId/agentId/pairId/callId`、类型、规范化 `sourceRef`、观察时间、资源版本（文件 hash 或可得的 revision）、读取范围、有限预览、截断标志、可续读状态。文件的活跃去重键至少是“资源身份 + 版本 + 区间”；同文件不同区间可共存。新版本使旧版证据退出活跃选材，但不改写历史观察。来源已变、不可回读和读取失败必须与“空结果”区分。

原始正文处理按来源决定：文件可在 hash 一致时重读；网页新抓取只能标为新观察，不能冒充旧快照；不可重读的结果只保留明确的有限预览，必要时通过现有附件/产物机制显式保存。不要为此另建完整材料库。持久化内容、审计摘要和当轮模型结果必须有清楚的不同合同。

### 3.2 编译与预算

ContextCompiler 为 WorkspaceFocus 与 ToolObservation 建立独立 Region，按本轮明确提及、当前焦点、近期有效引用、来源版本和 token 预算确定材料。当前 ReAct 已收到的工具结果不在同轮重复注入。Region Manifest 记录选中、未选中、过期、版本变化、截断及来源；外部正文作为数据，不能提升为系统指令。

每次 ReAct 调用模型之前重新计算完整输入与输出预留，包含新工具结果。工具自身负责对超长结果提供有用预览、范围读取或续读入口；不在模型请求前静默截掉用户要求读取的范围。若旧历史占满容量，才对有明确切点的旧过程生成一次 WorkContinuation：保留有效目标、纠正、已验证事实、未决事项和来源引用，近期原文与准备期间新增内容保持原样。首期复用现有模型/进程按需执行，不设常驻后台 Agent，不逐轮摘要；失败时保留原输入并给出容量错误。

回滚对话轮次时同步撤销对应观察与摘要覆盖关系。切换话题只改变活跃选材，不删除可追溯历史；向自治 Application 移交任务只传目标、授权资源引用和必要交接信息，由 Application 自己编译上下文。

### 3.3 文件执行路径收敛

逐步让旧 `WorkspaceService` 文件工具与 `VirtualWorkspace`、工作区 HTTP API 使用一致的路径解析、版本校验和原子写入语义。Agent 读取和编辑器保存应能核对同一文件版本。此项只收敛现有能力，不引入 LSP 或 IDE 级项目索引。

## 4. 前端微调

1. 在对话输入区和工作区 Copilot 使用同一条轻量“本轮材料”栏：显示当前文件、可选选区、当前终端及显式附加材料；发送前可移除单项。默认仅传文件身份与已保存版本，未保存正文不自动发送。用户主动加入选区时标明它是客户端草稿。
2. 后端核验焦点文件是否属于当前 Agent 的授权范围、版本是否匹配、终端是否属于当前 Thread 的 ExecutionSession。普通与流式聊天走同一 `WorkspaceFocus` 合同。真实 Thread 尚未加载时，不用 `workspace-{agentId}` 假身份创建文件/终端会话。
3. 心流面板仅显示私有目标与事实，移除“工作上下文正文、剩余轮数、清空”控件。在消息或工作区旁提供可折叠“已参考材料”：来源、范围、版本、已变化/已截断状态，以及打开来源或重新读取入口。展示的是服务端实际采用的 Manifest，不要求用户手动整理正文。
4. 切换 Agent/Thread 时清理本轮焦点和终端引用；保留现有编辑器未保存缓冲的保护。当前材料栏不变成常驻项目索引面板，也不为每轮增加确认弹窗。

## 5. 实施顺序

| 阶段 | 交付内容 | 完成判据 |
| --- | --- | --- |
| A：边界校准 | 统一真实 Thread、流式/非流式焦点传递、后端焦点校验；修复截断后解析与正文持久化合同 | 同一焦点在两种聊天路径行为一致；跨 Thread 终端不能误用；审计数据无意外正文 |
| B：观察记录 | 建立结构化 ToolObservation，替换自动正文追加；保留现有工具首次返回质量 | 同文件不同范围均可续用；变更文件被标为旧版；失败/空/不可回读可区分 |
| C：统一编译 | WorkspaceFocus/ToolObservation Region、确定性选择、Manifest、每次模型请求前预算 | 工具续接不会超窗后静默丢材料；Manifest 能解释每项材料去留 |
| D：按需续接 | 仅在容量需要时生成 WorkContinuation，保留近期原文与历史入口；回滚接线 | 摘要失败不损坏历史；新增内容不重复总结；回滚不留下未来证据 |
| E：前端与清理 | 本轮材料栏、来源视图；停用 `manage_work_context`、旧槽位和轮数设置；更新活动规范 | 日常工作无需手动维护上下文；旧数据可安全过渡后移除旧读写路径 |

旧 `workContext` 数据不升级为版本化证据，也不再进入模型；`0001_remove_work_context` 迁移删除历史列与逐轮记录。运行时读写路径及轮数配置已移除。每阶段只验证对应行为，最后再运行相关类型检查与回归测试。

### 2026-09-29 实施记录

- A/B/C/E 的核心链路已接通：真实 Thread 与焦点校验、结构化 ToolObservation、编译选择与 Manifest、前端材料栏，以及停用手动工作上下文工具和产品控件。
- D 已实现本轮 ReAct 容量压力下的按需工作续接；较早的可重读工具结果生成派生摘要，最近一次读取保留原文，失败时给出容量错误。跨轮权威仍由原始 Thread 历史和 ToolObservation 提供。
- 旧工作上下文只读过渡仍在；历史表与配置字段暂留，待旧数据自然过期和单独迁移。旧 `WorkspaceService` 与 `VirtualWorkspace` 的文件执行路径尚未完全收敛，当前焦点与范围读取已共享 SHA-256 版本语义。

### 2026-09-30 收敛记录

- 旧工作正文退出 `FlowStateService` 投影、Context Compiler 和记忆配置 API；旧数据库列与记录保留为历史归档，不再写入新正文。
- 旧文件读写、删除、元信息和目录列表工具改用 `ExecutionSession` / `VirtualWorkspace`；搜索工具也复用其只读路径解析。`read_file` 的观察记录直接接收读取时的 hash 和范围；`write_file` 支持原子追加及可选 hash 冲突保护。

### 2026-09-30 数据库迁移收口

- 新增标准 Drizzle `0001_remove_work_context.sql`、journal 条目与当前 schema 快照；新库执行 `0000→0001`，既有单基线库由薄层登记 `0000` 后执行后续迁移。
- 迁移保留私有目标、私有事实及工具观察，删除旧工作正文列、修订列、逐轮表和记忆配置中的轮数键。Schema、Repository 和启动补丁中的对应业务逻辑已删除。

## 6. 关键验收场景

- 连续读取同一文件第 1–80 行和第 500–580 行，两段都可被当前任务引用；修改文件后旧段不再被当作当前正文。
- 搜索同一文件的多个命中不会只保留最后一条；大结果有明确截断和续读入口。
- 用户切到工作区、选中未保存文本并发送后，Agent 能区分草稿选区与磁盘文件；普通与流式聊天一致。
- 工作区终端、文件树和 Copilot 使用同一个真实 Thread；切换 Thread/Agent 后不能沿用旧终端。
- 多轮轻量工作无需 `manage_work_context`；输入紧张时只压缩有明确来源的旧过程，近期工具结果和用户纠正仍保持原文。
- 对话回滚后，对应工作观察与续接摘要不再进入模型；文件历史快照仍按现有回滚规则处理。
