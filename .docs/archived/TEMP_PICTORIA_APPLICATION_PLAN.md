## 1. 已确认的产品与架构决策

以下来自本轮讨论，施工时不得重新解释成另一种产品：

1. 在 infOS 内新建自治子应用，采用与 Arca 同方向的 Application 接入架构，做到可以实际交付的程度。
2. 新写前端、设计与交互。外部 Pictoria 项目只作为经验参考，不复制其界面、代码、数据或 Tauri 宿主。
3. 创作画布与工作流编辑器是两套功能。画布是日常创作现场，工作流编辑器用于编排背后的处理能力；二者不是同一张图的两种视图。
4. 用户可以向画布或工作栏输入图片、视频、文字，再选择下一步如何处理。
5. 提供图像编辑、视频生成、抠图、超分、LLM 分析等通用步骤；工作流启用后自动封装成可调用步骤。
6. 工作流节点可以调用本地服务、在线 API、LLM、基础媒体处理，以及可复用的已发布工作流。
7. 为 Agent 提供丰富的结构化业务接口及 DSL，支持一次调用配置多个操作、创建画布或提交工作流。
8. 主 Agent 侧保持一个工具入口。执行完成后，指定结果自动回到发起任务的聊天；详细创作留在子应用。
9. 步骤作者通过自然语言声明输入要求，动态提供给主 Agent。系统不猜测未知模型的提示词偏好，不自动增加提示词转换步骤。
10. schema 校验必须保留，负责 API 字段、必填项、数据类型、范围与资源引用正确性；不负责判断提示词是否符合某个模型的审美。
11. 通用步骤的模型习惯、正反提示词用法等，由使用者在配置中补充说明；填写一次后可长期提供给 Agent。
12. 提示词库、图库等作为小型子页面提供。
13. 主—子应用之间通过声明、能力契约、受限适配与标准任务／资源协议交互。
14. 按后续确认，前端可采用独立的非像素创作工具视觉；本轮先完成后端。

### 1.1 本计划采用的实现建议

下列是为施工补充的默认技术决策，不冒充用户已经指定的具体接口或供应商：

- 名称与目录暂定为 `Pictoria`、`infos.pictoria`、`packages/apps/pictoria`，独立于外部同名项目。
- DSL 第一版采用版本化 JSON，表达资源、节点、连接、参数、画布放置和指定输出。
- 工作流第一版为有向无环图，支持串行、并行分支、集合输出与子工作流；循环和任意脚本不进入首轮范围。
- 采用 Vue 客户端与独立 Node Host，沿用仓库已有 SDK、协议和发行方式；画布与节点库在施工时针对交互能力评估，不为选库扩张任务。
- 领域数据使用独立 SQLite 与正式版本迁移，资源文件进入独立受管目录；实现上优先复用已有数据库基础能力。
- 第一个专用绘图提供商优先评估 AtlasCloud，但必须在接入时确认实际接口；不把外部 Pictoria 的模型 ID、参数、价格当作当前事实。
- 本地服务首先通过用户配置的 HTTP 服务接入；自动下载模型、安装 GPU 环境和托管任意本地程序暂不列入本轮。

## 2. 交付目标与范围

### 2.1 成品级的含义

完成标准不是“一个绘图页面能打开”或“一个 API 能返回图片”，而是：

- [ ] 全新子应用可以安装、启动、连接、断线恢复、停止、升级，并给出可操作的故障信息。
- [ ] 画布创作、工作流编写、封装步骤、Agent 调用使用相同业务接口。
- [ ] 图片、视频、文字可进入创作流程，结果可继续作为下一次输入。
- [ ] 后台任务独立于页面与一次聊天请求，关闭标签页不会取消已经接收的任务。
- [ ] schema 校验、授权、幂等提交、持久化、进度、取消、恢复、结果保存和交付形成闭环。
- [ ] 真实可用的步骤才进入可执行目录；未配置的能力显示配置入口与原因，不伪装可用。
- [ ] 主应用聊天、工作区协作聊天与已有社交渠道能接收发起任务的结果。
- [ ] UI 同时适配明暗主题、键盘、不同窗口大小和减少动态效果设置。
- [ ] 开发版和发行版都有完整资源与启动路径，不依赖作者机器的源码目录、固定端口或绝对路径。

### 2.2 本轮产品范围

- 创作项目、无限画布、工作栏、素材输入、选中后执行步骤。
- 图片／GIF／SVG、视频、文字的展示与引用；具体视频播放能力遵循平台编解码支持。
- 图像生成／编辑、视频生成、抠图、超分、LLM 分析等步骤定义与服务映射。
- 工作流编辑、输入输出与参数暴露、自然语言说明、验证、发布、版本化、封装为步骤。
- 可配置的同步／异步 HTTP 服务节点，以及受授权的 infOS LLM 节点。
- 提示词库、素材／作品库、执行记录和服务配置。
- 一个 Agent 工具、一次调用提交多操作、异步结果回传、打开具体画布。
- 必要的通用 Application 基础设施完善与 Arca 接入回归。

### 2.3 本轮不扩展的内容

- 不迁移外部 Pictoria 的 Tauri、移动端、桌宠或局域网同步功能。
- 不制作完整 Photoshop 图层绘画工具，也不引入扩散模型底层采样节点体系。
- 不内置任意代码执行、循环编程语言、完整插件市场或多用户实时协同编辑。
- 不把补齐整个 Arca 产品列为前置条件；只迁移被本次通用化影响的接入代码。
- 不重新实现 infOS 主 Agent 的聊天、记忆和重任务 harness。
- 不虚构图像／视频生成 Token 用量；LLM 节点沿用真实 LLM 用量记录。

## 4. 三部分职责与依赖

```text
infOS 主 Agent／任务中心／聊天／应用标签页
                  │
         infOS 侧集成与兼容层
    声明注册、授权、工具投影、任务投影、交付
                  │ 标准 Application Protocol
         Pictoria 侧适配与兼容层
    Manifest、Provider、资源桥、任务桥、宿主客户端
                  │ 稳定的应用内业务接口
              Pictoria 主体
    创作画布、工作流、服务适配、任务、图库、提示词库
```

### 4.1 infOS 侧

- [ ] 通用连接、身份、版本与能力绑定，不理解画布节点或绘图 API 私有字段。
- [ ] 工具说明和 schema 来自应用声明与动态目录，不由主应用硬编码每个模型。
- [ ] Surface 入口、应用状态和任务操作由声明映射到已有主 UI。
- [ ] 主应用保存调用来源、授权、任务关联、交付记录与资源映射。
- [ ] 主应用只投影子应用任务，不另建一套会自主推进绘图步骤的执行器。
- [ ] 保持现有 Thread 模式、能力门控、工具禁用和审批规则有效；应用在线不等于自动得到全部权限。

### 4.2 Pictoria 适配层

- [ ] 声明 Endpoint、Offer、Requirement、Tool Projection 与 Surface。
- [ ] 将外部操作转为项目、步骤、工作流与执行服务调用。
- [ ] 把领域任务转换为标准快照与事件，保留稳定任务 ID 和可恢复的领域阶段。
- [ ] 输出动态目录、使用说明、参数 schema 与版本。
- [ ] 通过受限能力申请访问 infOS 模型、授权资源与文件；不得读取主数据库或深路径导入 Backend。
- [ ] 结果事件携带资源引用，由宿主交付；不能直接写主 Thread 或社交适配器内部状态。

### 4.3 Pictoria 主体

- [ ] 项目、工作流、步骤、执行、资源、提示词拥有独立持久状态。
- [ ] 领域服务不依赖 infOS 内部对象、Vue 实例或 Electron BrowserWindow。
- [ ] Client 通过 Pictoria API 操作主体；用户与 Agent 使用同一服务层和校验逻辑。
- [ ] 外部绘图服务凭据由 Pictoria 服务配置持有并安全保存，不进入 manifest、工作流导出、日志或工具参数。
- [ ] 使用 infOS 模型时经能力调用，不获得 infOS 原始模型 Key。
- [ ] 与 infOS 断线时，已接收且不依赖宿主的任务可继续；依赖宿主的节点进入明确等待／失败状态，结果交付待重连恢复。

| ApplicationTaskProjection | 宿主任务中心展示及操作映射 | infOS，内容来自 Pictoria |
| Delivery | 来源路由、目标、输出集、交付状态、幂等记录 | infOS；Pictoria 保留关联与事件回执 |

### 6.1 版本与资源关系

- [ ] 画布布局和创作来源关系分别记录；拖动位置不创建工作流依赖。
- [ ] 素材引用、描述卡、运行占位和结果卡拥有稳定 ID。
- [ ] 编辑图片产生新资源，不覆盖原图；保存来源步骤、原始输入与参数快照。
- [ ] 修改工作流／步骤不会修改正在执行的 Run；重跑创建新的 Run／Attempt。
- [ ] 发布工作流有不可变版本，草稿修改不会悄悄改变现有步骤行为。
- [ ] 删除画布卡片不自动删除被其他项目、图库或任务引用的文件；资源清理由引用关系决定。
- [ ] 资源访问按用户／授权范围隔离，画布 ID 或资源 ID 不等于访问凭证。

## 7. 创作页与交互

### 7.1 画布

- [ ] 无限平移、缩放、适应全部、定位选中项、缩略导航及视口状态恢复。
- [ ] 拖入文件、粘贴图片／文字、从图库选择、从主聊天资源打开。
- [ ] 图片／视频／文字卡片、基础分组、多选、移动、删除、复制引用。
- [ ] 多选素材后可以指定输入角色与顺序，尤其是“主体图／参考图”等多个图片字段。
- [ ] 选中内容后显示就近的操作栏与适用步骤，未选中时保持画面安静。
- [ ] 新结果就近放置，保留来源标识与“继续处理”入口；自动布局避免覆盖现有素材。
- [ ] 执行占位卡展示排队、上传、执行、保存、失败等状态，可打开详情、取消或重试。
- [ ] 文本结果可阅读、复制、作为下一步输入；大段文字不撑爆画布缩略卡。
- [ ] 撤销／重做覆盖画布编辑；撤销布局或删除占位不等同于取消远程付费任务。
- [ ] 自动保存、保存中／失败反馈与重新加载后的状态恢复。

### 7.2 工作栏与步骤面板

- [ ] 工作栏接收素材及文字，支持多输入槽与参考图顺序。
- [ ] 按选中输入筛选适用步骤；允许补齐缺失输入，不把不可用步骤伪装成成功。
- [ ] 配置界面由输入 schema 与独立 UI 元数据生成，支持文本、数字、枚举、布尔、资源、数组和基础对象。
- [ ] schema 使用 API 字段名；UI 标题、帮助、字段顺序、控件类型独立配置，避免混用。
- [ ] 正向、负向提示词等作为普通声明字段呈现；是否字符串／数组由步骤作者决定。
- [ ] 显示步骤作者的自然语言说明，详细参数按需展开。
- [ ] 本次输入和常用默认值分开保存，不把一次临时修改覆盖为全局配置。
- [ ] 执行前显示任务数量与关键输出设置；具体费用只在服务返回可靠信息时展示。
- [ ] 工作栏可收起、调整占用；窄窗口下保持输入、执行和返回操作可达。

### 7.3 主 UI 入口

- [ ] 新标签页和应用入口可打开 Pictoria；从聊天结果卡直接定位 Project／Run／Asset。
- [ ] 同一项目重复打开优先聚焦已有标签，多个项目可按应用声明支持独立标签。
- [ ] 图库选图、主聊天引用和工作区资源通过标准资源桥输入，不传递未经授权的任意路径。
- [ ] 标签页关闭只释放 Client 视图；停止 Host 是独立操作，需显示受影响任务。

## 8. 工作流、步骤与 DSL

### 8.1 工作流编辑器

- [ ] 独立工作流页面，提供节点库、输入／输出端口、连线、参数编辑与验证反馈。
- [ ] 从素材输入、本地／在线服务、LLM、基础媒体处理等节点构建流程。
- [ ] 区分执行连接和编辑器位置，校验循环、悬空引用、缺失输出及字段连接兼容性。
- [ ] 可暴露工作流输入、内部参数、默认值、输出集与主要输出。
- [ ] 可引用已发布子工作流，锁定版本并拒绝递归引用。
- [ ] 保存草稿、验证、发布、停用与创建新版本。
- [ ] “可发布”与“当前可执行”分开：结构有效但服务离线／缺凭据的工作流应显示原因。
- [ ] 发布后自动生成 StepDefinition，创作页和 Agent 目录共用该定义。
- [ ] 画布调用封装步骤后，记录其 Run 与最终输出；内部节点详情在执行视图展开。

### 8.2 自然语言说明与 schema

- [ ] 每个步骤支持 `usageDescription`；可描述模型、提示词习惯、参考图用途、参数注意事项及简短例子。
- [ ] 通用步骤允许使用者填写服务／模型专属说明，并明确映射到生效步骤。
- [ ] 说明为工具文档，不拼进实际生成提示词，不覆盖用户提供的参数。
- [ ] 不内置“自然语言必须转换为 tag”等规则，不自动插入 LLM 节点。
- [ ] 用户主动编排的 LLM 润色／分析节点正常支持，与系统自动转换区别明确。
- [ ] 后端校验实际输入 schema：required、类型、枚举、数值范围、数组数量、额外字段与资源类型。
- [ ] 校验采用明确的 JSON Schema 子集／版本，前后端共享解释方式；不支持的关键字在保存时报告。
- [ ] 表单校验只是提示，后端执行前再次校验；错误包含字段路径、原因与预期结构。
- [ ] 不使用简单正则推断自然语言与标签语义，不以文案相似度替代字段校验。

### 8.3 DSL 契约

- [ ] 版本化 JSON：`version`、输入资源、节点／步骤、连接、参数、指定输出、可选画布放置。
- [ ] 用户节点编辑器与 Agent DSL 调用同一工作流编译器。
- [ ] 一次请求可创建项目、导入已授权资源、定义多个操作并提交执行。
- [ ] 引用采用明确结构，例如输入引用和节点输出引用；普通提示词字符串不做隐式表达式替换。
- [ ] 结构校验与权限预检在外部服务调用之前完成；请求失败时不留下半个已发布工作流。
- [ ] 项目创建与执行记录可在本地事务中落盘；网络调用不能假装属于可回滚数据库事务。
- [ ] 未给布局时自动排版，不要求 Agent 为每张卡片填写坐标。
- [ ] 支持调用已有步骤／工作流，以及修改指定草稿节点；避免每次重传整个项目。
- [ ] 限制节点数、展开深度、并行数、输出数与输入大小，参数集中配置并在文档中说明。
- [ ] 首版不支持任意 JS、动态代码求值、隐式循环或无限递归。

### 8.4 结构示意

下面仅表示契约方向，字段名称应在施工 P0 阶段固定为正式 schema：

```json
{
  "version": 1,
  "project": { "mode": "create", "title": "角色处理" },
  "inputs": { "portrait": { "resourceId": "host-resource-id" } },
  "nodes": [
    {
      "id": "edit",
      "stepId": "configured-image-edit",
      "stepRevision": 3,
      "inputs": { "image": { "input": "portrait" } },
      "parameters": { "instruction": "把外套换成白色，保留人物特征" }
    },
    {
      "id": "upscale",
      "stepId": "configured-upscale",
      "stepRevision": 1,
      "inputs": { "image": { "node": "edit", "output": "image" } },
      "parameters": { "scale": 2 }
    }
  ],
  "outputs": [{ "node": "upscale", "output": "image" }]
}
```

回传目标、调用者身份和幂等键由 infOS 在调用上下文中绑定，不能信任模型填写任意 Thread／QQ 会话作为交付目标。

## 9. 服务适配与通用节点

### 9.1 服务配置模型

- [ ] 区分服务配置、模型／操作配置、StepDefinition，允许多个步骤使用一个服务。
- [ ] 配置地址、认证方式、凭据引用、超时、并发限制与返回资源格式。
- [ ] 分开“连接正常”“支持所需操作”“当前可执行”，验证 Key 不自动产生付费作品。
- [ ] 保存与导出时脱敏；URL、请求体、响应日志中可能包含的凭据需统一清理。
- [ ] 读取服务实际能力或由用户声明能力，不从模型名字猜测支持文生图／编辑／视频。
- [ ] 服务切换后重新校验字段映射与步骤 schema，不能沿用失效参数静默执行。

### 9.2 首轮适配能力

- [ ] 专用在线图像适配器：至少打通真实图像生成／编辑中的可用能力，按实际服务返回处理结果。
- [ ] 通用同步 HTTP：请求字段映射、响应字段映射、JSON／二进制／资源 URL 输出。
- [ ] 通用异步 HTTP：提交、提取任务 ID、查询状态、成功／失败映射、输出提取与可选远程取消。
- [ ] 文件上传：multipart、受管资源上传或服务支持的引用格式；不把所有视频转为大块 base64。
- [ ] 本地 HTTP 服务：支持用户配置的本机／局域网服务，与在线服务共用声明式映射。
- [ ] infOS LLM 节点：模型候选、选择、文本／多模态输入按实际授权能力提供，结果回到工作流。
- [ ] 基础图片处理：裁剪、缩放、拼接等本地确定性操作；抠图／超分按配置的服务执行。
- [ ] 视频生成通过真实服务或通用异步 HTTP 接入；没有服务时保留配置入口，不返回占位视频冒充完成。
- [ ] 通用字段映射支持受限路径、显式输入绑定和常量，不通过任意代码表达式实现。

### 9.3 调用行为

- [ ] 只对确定可安全重试的上传／查询／下载自动重试；付费提交遵循提供商幂等能力。
- [ ] 支持多个结果、部分失败、较长视频等待和无百分比进度的服务。
- [ ] 明确单节点超时、整次执行期限、等待用户与断线等待的差别。
- [ ] 取消能力声明为远程可取消或仅本地停止；界面及工具结果明确区分。
- [ ] 下载与导入有大小、时长、格式限制和可读错误；网络故障可恢复，不把半个文件登记为完整资源。

## 10. 主 Agent 工具与动态描述

### 10.1 单工具入口

暂定 `pictoria`，具体名字在 P0 固定。内部 Operation 可以丰富，不等于为主 Agent 创建大量工具。

- [ ] 支持查看步骤／工作流定义、创建或更新画布、运行已有步骤／工作流、提交 DSL、查询和取消执行。
- [ ] 通过 action 分支 schema 约束各操作参数，执行相关参数再由选中步骤 schema 校验。
- [ ] 一个调用可以完成项目与多步骤提交，不要求主 Agent 手动上传、轮询、下载并再调用发送工具。
- [ ] 接收成功立即返回 `accepted`、稳定 Run／Task ID、项目入口及简短阶段，不阻塞等图。
- [ ] 继续聊天、结束本轮 ReAct、关闭主聊天或工具等待超时，不取消已交接任务。
- [ ] 主 Agent 可查看进度，但完成通知不依赖它持续轮询。

### 10.2 动态目录与说明

- [ ] 子应用输出版本化目录，含步骤 ID、版本、输入／输出、参数 schema、自然语言说明和可用性。
- [ ] 新建／发布／修改／停用工作流、服务配置变化时产生目录变更事件。
- [ ] infOS 在下一次模型请求组装时更新工具说明与参数定义；一条正在发出的模型请求使用固定快照。
- [ ] 使用当前生效步骤的作者说明，不能用全局通用文案覆盖未知模型要求。
- [ ] 目录较小时可直接附加可用步骤说明；较大时提供精简目录，并按选中／近期／明确引用的步骤加载完整说明。
- [ ] 若完整说明未载入，Agent 可以通过同一个工具读取；不截掉关键输入要求后假装已经告知。
- [ ] 执行绑定步骤／工作流版本；说明或 schema 已变化时，在外部调用前提示刷新定义。
- [ ] 当前没配置好的步骤不作为可执行选项注入；管理页仍可展示原因。
- [ ] 工具只随应用就绪、授权和用户启用状态进入列表；断线后撤销可调用入口，保留已提交任务投影。
- [ ] 在“工具与扩展”提供薄管理入口与聊天模式开关，详细服务／工作流配置跳转 Pictoria，不复制到主应用。
- [ ] 聊天模式默认是否开放采用现有扩展习惯，建议默认关闭；工作模式也必须服从用户禁用与审批。

## 11. 成品级 Application 接入

### 11.1 声明与公共基础设施

- [ ] 通用 Manifest 校验：Endpoint、Offer、Projection 引用一致，操作存在，工具名不冲突，版本可协商。
- [ ] 工具投影器按 Endpoint／Offer 绑定，不写死 `document.semantic` 或 Pictoria 领域能力。
- [ ] 完善 `invoke` 与异步任务提交投影；不要把整条工作流执行塞进同步 RPC 的 deadline。
- [ ] 动态目录与说明通过明确契约更新，不允许子应用直接修改宿主 ToolRegistry。
- [ ] 通用 Surface 声明解析与 URL 获取，限制到已登记的可信应用源与具体资源入口。
- [ ] Arca 迁移到此次提取的通用部分，原有功能保持可用；留下兼容薄层时注明移除条件。
- [ ] 公共协议有版本，未知版本返回可诊断错误，不静默降级为不同语义。

### 11.2 进程与连接生命周期

- [ ] 托管启动、发现外部实例、连接、断开、重连、停止、崩溃后的恢复入口。
- [ ] 持久 App／Node 身份与短期 instance／generation 区分；Host 重启不改变领域 Run ID。
- [ ] 就绪条件包含 Host、数据库迁移、协议与必要 Provider 初始化，进程 spawn 成功不能直接当应用 ready。
- [ ] 用版本握手、身份核验和受限会话授权保护调用，不能仅凭 localhost 地址信任任意客户端。
- [ ] Discovery 校验进程与实例，清理失效记录；并发启动去重，防止两个 Host 同时写同一数据目录。
- [ ] 重连后恢复目录、任务与事件游标；旧实例的事件不能覆盖新实例状态。
- [ ] 停止仅控制本应用托管的进程；外部实例不能按 PID 随意终止。
- [ ] 显式停止时先持久化检查点并处理正在提交的操作，再收口 Worker 与网络连接。
- [ ] infOS 退出时不遗留无主托管 Host；远程已提交任务在下次启动按记录恢复查询。
- [ ] Host 崩溃或 Client 崩溃分别诊断，不把 Client 重载当成重跑任务。

### 11.3 权限与宿主能力

- [ ] 申请模型、资源、工作区读取等实际需要的能力；默认不申请人格、记忆和终端执行。
- [ ] 能力未授权时给出禁用原因与配置入口，不能从主应用内部 Service 绕过授权。
- [ ] 授权撤销后不再发起新的宿主能力调用；已生成资源与已提交的远程任务按明确策略处理。
- [ ] Client 使用受限应用会话，不继承主窗口完整 preload／IPC 权限。
- [ ] 局域网 HTTP 服务地址由用户配置并受能力范围约束；导入的工作流不能自行提升本地访问权限。
- [ ] 使用独立服务凭据引用，导入工作流需要重新绑定本机配置。

## 12. 执行、持久化与恢复

### 12.1 状态与事件

- [ ] Run 至少区分排队、运行、等待、部分完成、成功、失败、取消；需要人工确认的情况有明确原因。
- [ ] NodeRun 包含准备、上传、已提交、查询、保存等阶段，以及失败、取消、跳过。
- [ ] 内部状态映射到现有标准 ApplicationTaskState，复杂领域状态保留在详情中，不强迫所有应用新增相同状态。
- [ ] 无可靠百分比时展示阶段和完成节点数，不用随机进度或定时器假装推进。
- [ ] 事件有稳定 eventId、Run ID、顺序／版本；重复与乱序不会让完成任务回退为运行中。
- [ ] Run、NodeRun 更新与待发事件在同一数据库事务中落盘，采用可重试 Outbox。
- [ ] 宿主事件接收与投影幂等；有缺口时重新拉快照，保持子应用为数据权威。

### 12.2 幂等与提交不确定性

- [ ] 调用幂等记录持久化，作用域基于应用身份、调用者和请求键，不能只放内存或绑定一次进程 instance。
- [ ] 请求键相同且内容相同返回原任务；请求键相同但内容不同返回冲突。
- [ ] 外部服务调用前持久化提交意图，获得远程任务 ID 后立即保存。
- [ ] 支持提供商幂等键时向下传递；查询与下载可重试。
- [ ] “远程接受但本地未拿到／未保存 ID”进入提交结果不确定状态；不默认重新提交付费生成。
- [ ] 提供人工查询、绑定远程任务 ID 或明确重新发起的恢复入口。
- [ ] 已有远程任务 ID 的恢复只查询，不能重复提交；已完成节点复用其结果。
- [ ] 图片已生成但保存失败，展示结果待保存并允许重试下载，不重新生成。

### 12.3 调度与取消

- [ ] 工作流依赖编译一次，执行快照可在重启后复用。
- [ ] 独立分支按服务并发额度调度，集合输出记录每个结果的成败。
- [ ] 失败节点的下游停止／跳过，不影响无依赖的成功分支；最终状态区分全部成功与部分结果。
- [ ] 支持仅重跑失败节点及其后续，或用户明确选择重跑某个节点；产生新尝试记录。
- [ ] 已接收任务不继承主 Agent 的 AbortSignal；取消通过明确 task.cancel／run.cancel 发出。
- [ ] 远程支持取消时记录远程确认；只停止本地等待时明确可能继续计费／生成。
- [ ] 取消后到达的晚结果保存可追溯状态，不静默恢复整条流程或自动发送多余结果。

## 13. 资源、聊天回传与任务中心

### 13.1 资源桥

- [ ] 输入接受已有宿主资源、经授权的工作区文件、用户上传和在线 URL。
- [ ] 宿主提供可控传输或短期访问凭证，子应用不读取任意主应用附件目录。
- [ ] 输出落盘完成后登记类型、大小、尺寸／时长、内容校验值、来源和可访问入口。
- [ ] URL 结果及时保存为受管文件，不把可能过期的 URL 当作品的唯一内容。
- [ ] 支持大文件流式传输、断点／重试和视频 Range 读取，避免跨协议发送巨型 JSON base64。
- [ ] SVG 以受限方式展示，外部内容不能获得应用脚本权限；媒体解码失败可下载原文件。
- [ ] 宿主附件与子应用资源有稳定映射和保留策略；删除项目不造成已交付聊天图片突然失效。

### 13.2 结果交付

- [ ] 提交时由宿主记录发起 Agent、Thread、渠道、用户和授权上下文，模型不能伪造交付目标。
- [ ] UI 手动执行默认只回画布；来自聊天的执行默认回原聊天，可由用户设置减少通知。
- [ ] 只交付声明的最终输出；中间图、LLM 文本和调试信息保留在应用详情。
- [ ] 主聊天与工作区协作栏复用现有资源卡片，附带打开 Project／Run 和继续创作入口。
- [ ] 社交渠道复用已存在的媒体／文件发送端口，按渠道限制退化为文件或简短链接。
- [ ] 结果准备、宿主资源导入与消息投递分别持久化状态；其中一步失败不会把生成任务改成生成失败。
- [ ] 本地消息插入使用稳定交付键；外部渠道没有可靠幂等确认时，保留发送状态不确定，避免盲目重发。
- [ ] 宿主离线、Thread 被删除、身份解绑等情况保留作品与待处理原因，不发到当前打开的其他聊天。
- [ ] 完成／失败／等待用户的通知沿用现有规则，不为每个节点弹桌面提醒。

### 13.3 任务中心

## 17. 分阶段施工顺序

阶段用于控制依赖与审阅，不表示交付时允许永久保留不可用占位功能。

| 阶段 | 工作 | 阶段完成证据 |
| --- | --- | --- |
| P0：固定契约 | Manifest 扩展、领域模型、步骤 schema、DSL、状态／事件、资源交付契约、供应商范围 | 契约文档与代表性请求／结果样例一致；待核实供应商能力明确列出 |
| P1：应用基础 | 通用投影／控制器／Surface、Pictoria 独立 Host、数据库迁移、鉴权、Client 入口 | 静态依赖边界清楚；启动／停止／恢复与发行路径已实现；运行证据待授权 |
| P2：首条创作闭环 | 图像服务、步骤表单、资源输入、Run 持久化、画布占位与结果 | 用户与 Agent 都能通过相同接口提交；接受后独立执行，结果可引用 |
| P3：工作流与 DSL | 节点编辑、编译、输入输出暴露、发布成步骤、批量配置 | 画布步骤与 Agent 调用同一发布版本；错误在外部请求前报告 |
| P4：能力与辅助页 | 本地／在线 HTTP、视频、LLM、抠图／超分服务绑定、图库、提示词库 | 每项标明真实可用能力；导入输出能继续创作 |
| P5：宿主闭环 | 动态工具说明、Thread 门控、任务中心、结果卡片、社交交付、故障恢复 | 重连／重复事件不重复提交生成；交付失败可恢复 |
| P6：产品收敛 | 明暗主题、动效、性能、键盘、诊断、备份、发行资源、Arca 接线清理 | 无双重权威、无专用复制投影器、无死入口；验证状态如实记录 |

### 17.1 首个必须贯通的场景

1. 用户创建画布并上传图片。
2. 创建或配置“LLM 润色 → 图片编辑 → 超分”工作流，声明输入和使用说明，发布为步骤。
3. 创作页选择此步骤，填入要求，后台执行，结果在画布中出现。
4. 主 Agent 通过同一个步骤与 schema 提交任务，单次调用获得 taskId。
5. 关闭标签页后任务继续；完成结果回到原聊天，点击打开对应画布。
6. Host 重启后查询已提交任务，结果保存／聊天投递失败可单独恢复。

其中 LLM 润色是用户显式编写的节点，不是系统为 SD 模型自动加入的转换器。

### 18.2 需要另行获得用户允许的验证

以下列出有价值的验收场景；写在计划中不构成运行授权，也不允许借静态脚本执行应用调试。

- [ ] schema 不合法、跨范围资源、能力撤销、陈旧步骤版本：拒绝且没有外部调用。
- [ ] 相同幂等请求、重复事件、乱序进度、连接中断：不重复创建付费任务，不回退终态。
- [ ] 提交期间崩溃、已有远程 ID 后重启、下载中断：进入正确恢复分支。
- [ ] 一条分支失败、三个候选部分成功、仅重跑失败节点：保留成功资源且依赖正确。
- [ ] 关闭标签、结束聊天、工具调用取消：已接收应用任务继续；显式取消有效。
- [ ] 发布／修改／停用工作流：动态工具说明、schema 与实际执行版本一致。
- [ ] 本地聊天插入幂等、社交发送状态不确定、Thread 删除／解绑：结果不串会话。
- [ ] Host／Client 崩溃、外部实例、重复启动、协议不匹配、升级迁移失败：诊断与恢复正确。
- [ ] 图片、GIF、SVG、视频和长文本的真实交互，明暗主题、缩放、输入法与键盘。
- [ ] 发行资源真实启动、真实提供商小规模执行、视频编解码与大文件传输。

测试以这些业务风险为依据，不围绕按钮文案、CSS 值、DOM 层级、内部函数调用次数编写脆弱断言；不恢复测试覆盖率门禁。未获允许时可编写必要用例，但不得运行。
