# Tool Atelier 临时设计备忘

> 状态：实现期间的临时约束基线。完成全量替换并稳定后，再决定是否并入正式UI/UX规范。

## 目标

将ReAct工具调用从统一方框卡片重构为独立的工具视觉轨迹。工具发言与工具调用已分离，工具节点只表达动作、状态和结果，不承担Agent正文。

## 已确认决策

- 覆盖全部官方工具，不分批暴露半成品。
- 采用“行为原型 + 每工具视觉签名”，避免每个工具复制完整组件。
- 视觉调性：微像素机械、轻拟物、萌系微动；同时适配浅色与暗色。
- 工具执行中默认展开；结果到达后保留约600ms收束动画，然后全部自动收起。
- 成功、失败、拒绝、取消均自动收起，但必须通过轮廓与文字保持状态可辨识。
- 连续同类工具自动成链，完成后保留每个步骤节点，不合并成单一摘要。
- 参数、原始结果、调用ID、耗时进入Hover“数据端口”打开的统一技术详情抽屉。
- 语义摘要优先，原始JSON不直接污染时间线。
- 纯视觉反馈，不加入声音。
- 遵循`prefers-reduced-motion`，关闭循环动画，保留必要状态切换。

## 架构

1. `ToolTraceController`：状态、自动收起、用户展开锁定、技术详情。
2. `ToolSignatureHost`：按签名选择行为原型与工具变体。
3. `ToolChainConnector`：按链类型连接相邻同类工具。
4. `ToolTechnicalDrawer`：统一展示参数、结果、耗时和内部工具名。
5. Manifest签名：`archetype`、`variant`、`chain`、`motion`、`silhouette`、`summaryFields`。

## 行为原型

- `file-paper`：读取、文件信息、目录与范围。
- `edit-splice`：写入、编辑与差异。
- `search-radar`：文件、代码、日记搜索。
- `terminal-tape`：终端创建、命令、读写、等待、中断、关闭。
- `browser-space`：地址、点击、输入、滚动、页签、DOM、网络、上传下载等。
- `vision-frame`：桌面截图、浏览器截图和网页图片。
- `desktop-motion`：应用、窗口、鼠标与桌面自动化。
- `time-ticket`：提醒设置、查询和取消。
- `stronghold-scene`：房间、环境、管家与成员传唤。
- `system-module`：完成任务、技能、高级工具、心流、Host/App通信。
- `web-sheet`：网页抓取与结果纸带。
- `script-circuit`：脚本编排。

## 关键约束

- 结果已经存在才挂载的节点直接进入折叠完成态，不补播动画。
- 用户手动展开后取消当前自动收起计时；下一次状态变化可重新进入策略。
- 技术抽屉打开时保持节点展开。
- 错误不能只依赖颜色；必须有文字和破损/卡住轮廓。
- 链条在正文、原型变化、失败、审批、ReAct轮次变化处断开。
- 折叠后卸载图片、Diff、终端等重型结果视图。
- 自动收起不得抢焦点或造成滚动锚点跳动。
- 社区工具无签名时使用轻量Generic节点。

## 完成标准

- 全部官方工具均可解析为明确签名，不落入旧统一方框。
- 浅色、暗色、减少动态效果均通过。
- 键盘可展开，数据端口可访问，状态具备文字语义。
- 连续同类工具在Conversation Surface中形成轨迹链。
- 类型检查、组件测试和前端全量回归通过。
